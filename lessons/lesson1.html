Why a team?

✏️ Quick basics: an agent

An LLM can only write text. To make it do things, a small program reads what it writes. When the LLM writes ACT: and a request, the program does it and writes the result back into the text, on a LOOK: line. The LLM reads that and carries on.

Step through it. Watch who writes each line.

The LLM and the program together are an agent.
agent = LLM + a program that does what it asks

One agent can do a lot. Can it do a whole job alone?

A company in a chat

Think of a small company. Each person has one role, and they all talk in one group chat. You can do the same with agents. Here we call each agent in the chat a bot. Writing @ and a bot's name asks that bot to reply next.

Step through the chat. Watch who does what.

Three bots, each doing one part, in one shared chat. That's a team.
team = bots with one role each + one shared chat

All three are the same kind of agent. So what makes the Writer a writer?

What makes a role

Each bot gets its own instructions: text, placed before the chat, that says what its job is. Each also gets its own tools: the things its program can do when asked. Only the Researcher has search, so only it can look things up.
role = instructions + tools

Team or solo?

Every reply from a bot is one more time the LLM writes, so it costs time and money. One agent answering a question writes once. A team of 3, each replying once, writes 3 times: about 3 times as long.

A team is worth it when a job has parts that need different instructions or tools, or when one bot should check another's work. For a small, one-step job, one agent is better.

Team or solo? Pick for each job.
