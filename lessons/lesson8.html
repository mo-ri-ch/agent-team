A computer for each bot

One laptop, one set of files

Right now, when a bot runs a command, it runs on your laptop, with your files. Its own folder keeps its memory and keys apart, but its commands can reach everything you can. One wrong command from one bot can delete another bot's work, or yours.

Step through. Marketing is asked to “clean up old files”.

What if each bot had a computer of its own?

A computer inside your computer

A container is a small, separate computer that runs inside your laptop, made with a free tool called Docker. It has its own files. Commands run inside it can't see your laptop's files, and deleting something there deletes nothing of yours. Hermes calls this a sandbox.
what happens in the sandbox stays in the sandbox

Run the same command in each place. Compare.
$ rm *_old.csv

your laptop

Marketing's sandbox

Hermes also locks the container down: no extra system powers, and a cap on how many programs it can start.

🤔 Is it a real separate computer?
Not quite: it shares your laptop's processor and memory, but it gets its own files, programs and settings. That's why it starts in seconds, and why you set limits on how much memory it can use (coming up).

First, Docker itself.

Install Docker

On a Mac or on Windows, install the free Docker Desktop app and start it. On Linux, or inside WSL2's Ubuntu, one command installs it. Then check with a tiny test container: if it prints a hello message, Docker works.
install Docker → docker run hello-world

Pick your laptop.
  1. Download Docker Desktop from docker.com and install it.
  2. Start it, and wait until it says it's running.
  3. On Windows, in its settings, turn on WSL2 for your Ubuntu.
  4. In your terminal (Ubuntu on Windows):
docker run hello-world
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER

Log out and back in (or close and reopen Ubuntu), then:

docker run hello-world

The second Linux line lets you use Docker without typing sudo every time.

🤔 What is sudo?
“Do this as the administrator.” It asks for your password, because the command changes the system. Use it only for commands you trust, like these from Docker's own site.

Docker works. Now move a bot into it.

Switch a bot to its sandbox

Where a bot runs its commands is one setting in its own config.yaml: terminal.backend. It starts as local (your laptop). Set it to docker, and Hermes starts a container for that bot the first time it needs one, and keeps it for next time. Each bot gets its own.
terminal.backend: local → docker

Switch each bot. See its setting.

But now the bots can't share files at all.

Share one folder, on purpose

Some work has to pass between bots: Production writes the packing list, Operations reads it. So you mount one chosen folder into each container that needs it: the same folder, seen from inside. Everything else stays out of reach.
a bot sees only the folders you mount

Operations' sandbox

Files a bot makes anywhere else stay inside its container. To hand you a file, it must save it in a mounted folder.

One more thing: how big is each sandbox?

Set its limits

Containers share your laptop's memory. So give each one a cap with container_memory, in MB (1,024 MB = 1 GB), so one runaway bot can't freeze the laptop. Everything must fit together:
memory caps + local model + you ≤ laptop memory
4 bots × 1 GB + an 8 GB model + 3 GB for you = 15 GB: fits in 16 GB.

Set the numbers. Does it fit?
GB

In config.yaml: container_memory: 1024. container_cpu and container_disk cap processor and space the same way.
