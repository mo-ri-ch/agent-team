Jobs on a schedule

Jobs that start themselves

A scheduled job is a task a bot does by itself, at set times. You give it three things: when to run, what to do (a prompt, like a message you'd send), and where to send the result. The gateway checks every minute. When a job is due, it starts a fresh chat with that prompt, and sends the answer.
job = when + what to do + where to send

Step through one morning.

In Hermes these are called cron jobs. They run only while the gateway runs.

First: how do you write “every day at 9”?

Reading a schedule

Simple ones are plain words: every 2h, every 30m. For set times, a schedule has five slots: minute, hour, day of the month, month, day of the week. A * means “any”.
minute hour day month weekday
0 9 * * * = minute 0, hour 9, any day: 9:00 every morning.

Change the slots. Read it in words.

Times follow the clock of the computer running Hermes. hermes cron status shows each job's next run, so you can check.

Now a real job: the morning plan.

The morning plan

Every morning, Marketing sends the social media manager today's plan. Each run starts a fresh chat: the bot remembers nothing of the chat where you made the job. So the prompt must say everything: who it's for, what to include, and how long.
a job's prompt must stand on its own

Pick a prompt. See what the job sends at 9:00.

marketing cron create "0 9 * * *" "(the full prompt)" --name "Morning plan" --deliver telegram

--deliver telegram sends it to the bot's home chat. Pick it once: in that chat, send /sethome.

🤔 Can I just ask in a chat instead?
Yes: tell the bot “every morning at 9, send the post plan here”, and it makes the job for you, sent back to that chat. The command shows exactly what gets saved.

And if she forgets to post?

Only when needed

At 7 PM, a second job checks: did today's post go up? If yes, there's nothing to say. A reply containing [SILENT] is never sent, so the prompt says: “If the post is up, reply [SILENT].” A gentle nudge arrives only on the days it's needed.
reply contains [SILENT] → nothing is sent

Pick an evening. What arrives on her phone?

The job still runs every evening, so it still uses tokens. Only the message is skipped.

Now the whole team's week.

The team's week

Each bot keeps its own jobs, in its own profile, so you create each one with that bot's command: production cron create …. Together they make a rhythm for the business: a plan in the morning, packing in the afternoon, a check at night, and a report each Monday.
each bot's jobs live in its own profile

Turn jobs on and off. See the week.

The Analyst's report shows where this pace leads in 1, 2 and 3 years, always labelled as a projection, not a promise.

Do all these jobs need an LLM?

No LLM needed

Some jobs need no thinking. If you already know the exact message, or a small script can work it out, run the job with --no-agent: the script's output is sent as it is, and no model is used, so it costs nothing. If the script prints nothing, nothing is sent.
needs judgment → a prompt · fixed or countable → --no-agent
